# 速さの記録（わが家のご飯帖 Web 版）

2026-10-29 鷹野（開発本部）。オーナーの「アプリがサクサク動くように」への対応。ブランチ `claude/perf`（`claude/int` b9b8eba2 から）。

## 測り方

- 道具: `tools/qa/perf.js`（run-all には入れていない）。`NODE_PATH=$(npm root -g) node tools/qa/perf.js http://localhost:8886/`
  - 環境変数: `RUNS`（起動を測る回数。既定 5）、`REPS`（操作を測る回数。既定 6）、`CPU`（既定 `1,4`）
- 画面は 390×844（isMobile・タッチ・DPR 3）。日本・日本語・3品、オンボーディング済みの状態から。外のサイト（Google・Wikimedia・GitHub の remote.json）は止める。
- CPU は「そのまま」と「4倍遅く」（CDP の `Emulation.setCPUThrottlingRate`）。
- 起動: ページを開いてから、お膳に料理が入って次の描画まで（献立まで）／お膳の料理の絵（SVG）が届くまで（絵まで）。初回（Service Worker なし）と2回目（SW 登録後に読み直し）。
- 操作: 本物のタップ（Playwright の `tap`）で、click の始まりから次の描画（rAF → 次のタスク）まで。まるごと入れ替え／かえる（候補のシートを開く・候補を選ぶ）／タブ（さがす・記録・今日）／設定を開く・今日へ戻る。中央値。
- Long Task は PerformanceObserver（50ms 以上）。
- 前と後は、同じ時間帯に2つの静的サーバー（前 = b9b8eba2 のコピー、後 = このブランチ）へ続けて測った。同じマシンでほかの担当のテストも動いていたため、1回ごとのぶれは大きい（特に「最大」）。中央値で見ること。

## 残った遅い所（次に直すなら）

1. **本体スクリプトの読みこみ・実行（起動の Long Task 4倍で 500〜900ms）**。index.html の中の 1.33MB の inline script は V8 のコードキャッシュが効かない（毎回、読みこみ・コンパイルし直し）。外のファイル（app.js）に出して SW で保存すれば、2回目からコンパイルがほぼ要らなくなるが、13000行を動かすので、並行して index.html を直している人がいるあいだはできない。sw.js の SHELL に足すので、版を上げるのと一緒にやる必要もある。
2. **お膳の絵（SVG）の描画**。お膳の手描きの SVG（1枚 50〜100KB）は、CSS の背景として描くたびに重い（まるごと入れ替え 1回の Paint が 4倍で 80〜100ms）。同じ大きさの webp を用意すれば軽いが、見た目が変わりうるのでデザインと相談。
3. **お知らせの置き場所（toastPlace）**: かえる・決めるのあとに、画面の要素ごとに `getBoundingClientRect` と `elementsFromPoint` を見る（4倍で1回 約30ms）。お知らせの担当（三宅）の範囲なので触っていない。
4. **描き直しが画面まるごと**（render が `#view` の innerHTML を作り直す）。まるごと入れ替えでは、新しい画面のレイアウトが 4倍で 30〜70ms。統括の指示（画面の作りを最初の版に戻す）があるので、画面の作りを前提にした直し（お膳の部分だけ描き直すなど）はしていない。
5. 初回だけ: SW の SHELL の取りこみ（index.html をもう一度 1.48MB）が起動中に重なる。
