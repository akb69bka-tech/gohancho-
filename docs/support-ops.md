# 申請後・公開後の連携の決まり（オーナー × Claude）

作成: 2026-11-24。オーナーの指示は「Apple に申請する。サポート体制を万全にして、アップデートのやり方を Claude と連携して決めておいて。オーナーは『こういうのが来たから改修して』と言うだけにする」。
手順書（オーナー向け）: https://claude.ai/artifact/JPzqe9jv1ma3Co8MheyKDM 。窓口と担当は `ios-app/サポート体制.md`、版の出し方は `ios-app/アップデートの手順.md` と `docs/release-management.md`。この文書はそれらを「オーナーの一言から公開まで」の1本の流れにつないだもの。

## 1. オーナーの言い方（これだけでよい）
| オーナーが言う・貼る | Claude がすること | オーナーに返すもの |
| --- | --- | --- |
| 「こういうのが来たから改修して」＋声・レビュー・メールの本文 | 受付（緊急度を決める）→ 再現 → 直す → 全点検 → 試せるアプリを更新して右に開く | 「直した・試して」の一言と、次に押すボタン |
| 「Apple から差し戻された」＋ Resolution Center の本文 | 条項を特定 → 直すか説明するかを決める → 返信文（英語・和訳つき） | 貼るだけの返信文、直した版 |
| 「レビューに返事して」＋レビュー本文 | 返事の案（その国の言葉・和訳つき）。約束・返金の言い切りはしない | 貼るだけの文 |
| 「出して」「1.1.1 で申請して」 | 版を上げる → PR → （Merge のあと）iOS release を動かす | 「Merge を押して」→「審査へ提出を押して」の案内 |
| 「急ぎ」 | remote.json の notice 案をすぐ出す（審査なしで次の起動から表示）→ 直し → 優先審査の文 | お知らせの文と、優先審査の申請文 |

- 言葉は「回収」「改修」「直して」どれでもよい（声の入力の聞き違いも受ける）。
- 利用者の個人の情報（メールアドレス・名前）は、Issue・コミット・文書に写さない。本文の中身だけを使う。

## 2. 緊急度（`ios-app/サポート体制.md` の3と同じ）
- 🔴 起動しない・購入したのに使えない・データが消える・アレルギーや食の決まりの取りこぼし → その回のうちに notice 案と修正。安全に関わるものは案件B（北条／柊）に最優先で回す。
- 🟠 献立・レシピ・買い物メモが使えない → 1週間以内の版。
- 🟡 表示・翻訳・レシピの誤り → 次の版にまとめる。
- 🟢 要望 → 声の掲示板（docs/panel/board.md）に積み、月1で提案。

## 3. 直しから公開まで（毎回同じ）
1. claude/int で直す → `tools/qa/run-all.sh` 全項目合格 → 版上げ（sw.js・ASSET_V）→ claude/avoid-swap を早送りして push。
2. 試せるアプリを更新して、オーナーの右の画面に開く。
3. PR（claude/avoid-swap → main）の説明を最新にして、オーナーに「Merge を押して」。Web 版はここで届く。
4. iPhone 版: `ios-app/package.json` の version と index.html の `APP_VERSION` を上げる（不具合の直しは 1.1.1 のように末尾、機能の追加は 1.2.0）。Merge のあと「iOS release」を動かす（Secrets が登録済みのとき）。
5. オーナーが App Store Connect で「審査へ提出」。「この版の新機能」の文は Claude が出す。
6. 審査の結果をオーナーが貼る → 通れば改修ノートに記録、落ちれば 1 に戻る。

## 4. 見回りでの受付（自動）
- 2時間ごとの見回りと毎朝の確認で、GitHub の Issue #1（サポート窓口）と新しい Issue を毎回読む。新しいものは緊急度を付けて受け、PDF の先頭でオーナーに知らせる。
- オーナーが会話に貼った声は、その場で受ける（見回りを待たない）。

## 5. 申請の前に確かめること（2026-11-24 時点）
- **main は古い**: App Store に出す iPhone 版は main から組み立てる。main は 2026-10-24 のまま（PR #3 が未 Merge）。申請の前に PR #3 を Merge すること。いまの PR #3 の先頭は v163。v164 は全点検の最中。
- **課金**: billingMode は 'native'（iPhone 版はお試し1か月→月額300円）。「iOS release」は RevenueCat のキーと SUPPORT_EMAIL の Secrets がないと止まる（審査で落ちないための止め）。App Store Connect の有料 App 契約とサブスク製品 `gohancho_plus_monthly` も要る。最初のサブスクは、アプリの版といっしょに審査に出す（Apple 公式）。
- **連絡先**: アプリの「ご意見・不具合を送る」の宛先（SUPPORT_EMAIL）はオーナーが Secrets に入れる。Claude は個人の連絡先を書かない。
- **実機**: TestFlight でオーナーの iPhone で一度動かす（この環境では実機の確認ができない）。
