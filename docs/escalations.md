## Web版300円課金の準備（課金担当 / 2026-11-07）
オーナー指示: 「Web版もアプリ(iPhone)と同じように、300円の課金ができるようにしておいて」。**課金は有効にしていない**（`billingMode: 'off'` のまま＝全員無料）。契約・アカウント登録・キー設定・お金が動く操作は一切していない。ここにあるのは「オーナーが準備を済ませてスイッチを切り替えるだけで動く」ための下準備。
**注意: この作業環境は外部サイトを開けなかったため、下の料金・仕様は一次情報で確かめていない。「出典不明」「未確認」と書いたものは、契約の前にオーナー（または統括）が各社の公式ページで確かめること。**

### 料金（既決）
月額300円・年額3,000円（月額×12＝3,600円より600円お得）・どちらも最初の1か月無料。Web 版も同じ。

### 方式の比較
| 案 | しくみ | 購入の確認（いま有料か） | iPhone と購入を共有 | 判定 |
|---|---|---|---|---|
| **A. RevenueCat Web Billing（Stripe 連携）＝推奨** | RevenueCat の Web 用の購入画面（Stripe で決済）。Web SDK（purchases-js）を購入画面を開いたときだけ読みこむ | RevenueCat の公開キー＋購入ID（appUserID）で「プラス（plus）」の有無を取得。サーバー不要。公開キーは公開してよい種類 | できる。iPhone と同じ Entitlement「plus」を見る。同じ購入IDを両方で使う（下記） | 採用 |
| B. Stripe Payment Link / Checkout ＋ 顧客ポータル | Stripe の支払いリンクで買う | **できない**。サーバー（Webhook を受ける所）がないと「買った人」を安全に判別できない。リンクを開いたら有料扱い、は誰でも不正にできる | できない | 不採用 |
| C. Stripe ＋ 自前のサーバー（Cloudflare Workers 等） | Webhook で購入を記録し、アプリが問い合わせる | できる | 自前で作りこみ | 作りこみと運用が重い。A で足りないときの予備 |
- 静的 PWA（サーバーなし）で安全に確認できるのは A か C。A は RevenueCat が確認の役を持つので、サーバーを持たずに済む。iPhone 側が既に RevenueCat なので、購入の一元管理もできる。
- **購入IDの扱い**: Web は端末ごとに `web_…` の購入IDを作り、購入画面に表示する。iPhone など別の端末で購入画面の「別の端末の購入IDで復元」にそのIDを入れると同じ購入を使える（Web 側の実装済み）。購入IDは本人確認の代わりなので「他の人に見せない」と画面に書いてある。iPhone アプリ側の `logIn`（RevenueCat の appUserID を Web の購入IDにそろえる処理）は**まだ入れていない**（iPhone アプリのビルド・実機が要るため）。iPhone で買った人が Web で使う、の方向は、iPhone 側の購入IDを Web に入れる形で動くが、iPhone 側の購入IDを画面に出す処理が未実装。→ 未解決（下記）。
- 「アカウント（メール・パスワード）」は作っていない。作るなら認証サーバー＝費用と個人情報の扱いが増えるので、オーナー判断。

### オーナーがやること（順番に）
1. **事業者として販売する準備を決める**。日本で有料で売るので「特定商取引法に基づく表記」に事業者名・住所・電話番号（または請求があれば遅滞なく開示する旨）・メール・料金・支払い方法・解約・返金を書く。個人の住所や電話をそのまま出したくない場合の方法（バーチャルオフィス等）は費用や法的な可否があるので、必要なら専門家に確認（私たちは法的な確認をしていない）。
2. **Stripe のアカウントを作る**（事業者の本人確認・銀行口座の登録が要る。料金は下記）。日本円での決済・サブスクリプション（定期課金）を有効にする。
3. **RevenueCat のアカウント／プロジェクトに Web Billing を追加**し、Stripe をつなぐ。Entitlement `plus`（iPhone と同じ名前）を作る。商品 `gohancho_plus_monthly`（300円/月）・`gohancho_plus_yearly`（3,000円/年）を作り、どちらも**1か月の無料トライアル**を付け、Offering の Package を `$rc_monthly`・`$rc_annual` にする（名前を変えたら `PLAN.webPackages` を合わせる）。
4. **Web Billing の公開APIキー（`rcb_…`）をコピー**。秘密キー（`sk_…`）は絶対にコードに入れない。
5. **特定商取引法の表記ページ**と**Web 版の利用規約**を作って公開（どちらも URL が要る。例: `gohancho/` に `tokushoho.html` / `terms-web.html` を足す。プライバシーポリシー `privacy.html` に決済（Stripe/RevenueCat に購入情報が渡ること）を書き足す）。解約・返金のルールもここに明記（Stripe の決済は Apple の返金とは別。方針はオーナーが決める）。

### リスクと未解決
- **法務**: 特商法表記・利用規約・プライバシー・解約と返金の方針は、**私たちは法的な確認をしていない**。公開前に専門家の確認を（特に個人の住所の開示）。

- 外部の CDN（jsDelivr）から SDK を読む。購入画面を開いたときだけ。オフラインでは購入できない（無料の機能には影響なし）。固定の版・整合性（SRI）の追加はオーナーの確認後。

## 公開後の不具合の芽（品質保証 八木チーム / 2026-11-09）
実際に動かして確かめた結果（Chromium・Playwright）。直せる小さなものは直した（ブランチ claude/risk・テスト tools/tests/risk-r1.mjs）。ここはオーナー判断が要るもの。
1. **iPhone の Safari（ホーム画面に追加していない人）の記録が、7日使わないと消えるおそれ**
   - WebKit の決まり（ITP）で、ホーム画面に追加していないサイトの保存（localStorage・IndexedDB・キャッシュ）は、Safari で7日使わないと消される、と記憶している（WebKit の公式ブログ 2020年3月。**一次情報はこの環境で確かめていない**。webkit のブラウザもこの環境に無く、**実際に消えるかは未確認**）。
   - いまのバックアップのお知らせは「30日書き出していない」とき。7日より遅い。
   - 選択肢: A 今のまま／B iPhone の Safari で開いている人にだけ、最初の記録のあとに「ホーム画面に追加すると記録が消えにくい」を1回出す（画面の文言が増える）／C お知らせを7日に早める。おすすめ B（文言を足すのでオーナー確認）。
   - ブラウザ版（Chrome・Safari）には、記録を残した人だけ `navigator.storage.persist()` を頼むようにした（端末の空きが少ないときに消されにくくなる。7日の決まりに効くかは**わかりません**）。
2. **はじめて開くときの重さ**: `index.html` が 2.0MB（gzip で約 630KB）。サーバー側で 50KB/秒に落とすと、はじめての人はお膳が出るまで約40秒（圧縮なしの計測。圧縮ありならおよそ3分の1と見積もり・未計測）。2回目からは保存した画面で約3.3秒（ネットを3秒待ってから保存した画面）。分けて軽くするのは大きな作り替えなので、公開後の様子を見てから。
3. **プライバシーポリシーの空欄**: privacy.html の【公開日を記入】【運営者名】【連絡先メールアドレス】、`SUPPORT_EMAIL` が空のまま（A-2 と同じ。公開前に必須）。
4. **課金オフのまま「プランと購入」が出ている件（第31回 R146）**: Web・iPhone アプリ（を装った状態）とも、設定の見出しは「プランと購入」、中は「無料です」と「プラスの内容」。「プラスの内容」を開くと PLUS の機能の一覧と「無料です」。値段・購入のボタンは出ない。審査で「購入できないのに購入の見出しがある」と言われるおそれは**わかりません**（ガイドライン 2.1・3.1 の解釈）。選択肢: A 今のまま／B 課金オフの間は見出しを「プラン」にし、「プラスの内容」を隠す。決めるのはオーナー。
5. **iPhone アプリの許可の文言（マイク・音声認識）**: 料理中のハンズフリーでもマイクを使うので、文言に足した（ios-app/scripts/setup-ios.sh）。**Mac でのビルド・PlistBuddy での書きこみは未確認**（英語の文に “ ” の引用符を使った）。
6. **iPhone アプリの起動時の地の色**: capacitor.config.json の backgroundColor が生成り（#fbf5ec）だけ。暗い表示の人は、起動の一瞬だけ明るい地が出るおそれ（実機で未確認）。
