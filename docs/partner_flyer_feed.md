# 提携先のチラシデータ（特売フィード）の形式 — 案（v1）

担当: 機能開発部 椎名 陸 / 2026-11-04
状態: **形式と取りこみの関数だけ**。いまは提携先がなく、アプリは通信しない。提携・契約・費用はオーナーの判断（docs/escalations.md の「スーパーの特売」）。

## 1. なぜこの形か
- オーナーの指示（11/04）: 「よく行くスーパー」の特売を出し、特売の食材を使う料理を出す。将来スーパーから手数料（マージン）をもらえるように、**しくみの入口だけ**作っておく。
- チラシのサイト（Shufoo!・トクバイ・店のサイト）を**読みに行かない（スクレイピングしない）**。利用規約で禁じられていることが多く、チラシの画像には著作権がある。
- 提携が決まったら、提携先から**この形の JSON** を受け取り、アプリの「今日の特売」と同じ形に入れる（`mergeFlyerFeed`）。受け取る方法（ファイル・API・通信の有無）は、契約が決まってから決める。

## 2. 形式
```json
{
  "format": "gohancho-flyer-feed",
  "version": 1,
  "store": {
    "id": "partner-store-0001",
    "name": "ハッピーマート 駅前店",
    "area": { "pref": "東京都", "city": "練馬区", "zip": "176-0001" }
  },
  "valid": { "from": "2026-11-04", "to": "2026-11-05" },
  "currency": "JPY",
  "sponsored": false,
  "disclosure": "ハッピーマートから提供された特売情報です",
  "items": [
    { "key": "キャベツ", "name": "キャベツ", "price": 98, "unit": "1玉", "category": "veg" },
    { "name": "豚こま切れ肉", "price": 128, "unit": "100g", "category": "meat", "sponsored": true }
  ]
}
```

| 項目 | 必須 | 中身 |
|---|---|---|
| `format` / `version` | ○ | `"gohancho-flyer-feed"` / `1`。ちがえば読みこまない |
| `store.id` | | 提携先の店の番号（同じ店を見分ける。60文字まで） |
| `store.name` | ○ | 店の名前（30文字まで。制御文字・`<` `>` は除く） |
| `store.area.pref` / `city` / `zip` | | 地域（任意） |
| `valid.from` / `valid.to` | ○ | 特売の期間（`YYYY-MM-DD`）。`to` ≧ `from`、14日まで。`to` が今日より前なら読みこまない |
| `currency` | | ISO 4217（`JPY` `USD` など）。なければ `JPY` |
| `sponsored` | | `true` なら全部の品が広告（PR） |
| `disclosure` | | 広告であることなどの表示文（120文字まで）。画面にそのまま出す |
| `items[]` | ○ | 1〜100件 |
| `items[].key` | | アプリの食材キー（冷蔵庫と同じ canon。日本は「キャベツ」「豚肉」など） |
| `items[].name` | key か name | 表示名（30文字まで） |
| `items[].price` | | 数（0〜1000万）。単位は `currency` |
| `items[].unit` | | 「1玉」「100g」など（12文字まで） |
| `items[].category` | | `veg` `meat` `fish` `dairy` `other` `all` |
| `items[].sponsored` | | `true` ならこの品は広告（PR） |

知らない項目は無視する（`__proto__` なども読まない）。全体で 200,000 文字まで。

## 3. アプリの中の関数（gohancho/index.html）
- `importFlyerFeed(json, today)` → `{ok: true, feed}` か `{ok: false, err: 'json'|'shape'|'dates'|'old'|'items'|'size'}`。状態（S）は変えない。
- `mergeFlyerFeed(sale, feed, newId)` → `{sale: 新しい S.sale, n: 入れた件数}`。引数は変えない（純粋な関数）。
  - 同じ店（`store.id` か同じ名前）があればその店の特売に入れる。なければ、登録が3店未満なら店を足す（印 `fid`）。
  - 同じ店・同じ期間の提携データは入れ替える（2回読んでも重ならない）。
- 試すとき: 設定 →「よく行くスーパー」→「提携先のチラシデータを読みこむ（試験用）」に貼りつけて「データを読みこむ」。

## 4. 広告の表示（必ず守る）
- 提携データの品には、画面で必ず札を付ける: 広告（`sponsored`）は **「PR」**、それ以外の提携データは **「提携」**。表示文（`disclosure`）か、ない場合は「提携先から届いた広告（PR）を含む情報です」を出す。
- 根拠: 景品表示法の「ステルスマーケティング」の規制（2023年10月1日施行）。
  出典: 消費者庁「令和5年10月1日からステルスマーケティングは景品表示法違反となります」。
  **この環境から消費者庁のページの本文を開いて確かめていないため、題名の正確な言い回しと、どの表示で足りるか（「PR」「広告」「提携」のどれが求められるか）はわかりません。** 公開前に法務の確認が要る（escalations.md）。
- 献立（今日の一膳・決めた献立）を、提携先の品で自動で変えることはしない。提案の順番を提携でゆがめない（いまは食材の当たる数と時間だけで並べる）。

## 5. 個人の情報
- 店・地域・郵便番号・特売は**端末の中だけ**（`S.sale`）。バックアップの書き出しには入る（本人のファイル）。
- 提携先へ地域などを送るしくみは**作っていない**。作るときは、プライバシーポリシーの更新と本人の同意が先（escalations.md）。

## 6. チラシの写真から読む（iPhone アプリ。オーナー決定 11/04 の C）
- 自作プラグイン `ios-app/plugins/gohancho-flyer-text`（`FlyerText.recognize({image, languages})` → `{lines: [{text, confidence, x, y, w, h}]}`、`supportedLanguages()`）。Apple Vision の `VNRecognizeTextRequest`（端末の中・無料・外部送信なし）。写真は縮小して渡すだけで、保存しない。
- 品名と値段を拾うのは JS の `parseFlyerText(lines)`（純粋な関数）: アプリの食材（canon）に当たる語と、同じ行か次の行の「98円」「¥158」「128円（税込138円）」を拾う。「30円引」「10%OFF」「ポイント」は値段にしない。候補は**自動では入れず**、使う人が選んで「選んだ品を特売に入れる」を押す。画面に「読み取りの誤りがあり得ます」と出す。
- ウェブ版・プラグインのない iPhone では、ボタンを出さず「iPhone アプリで使えます」とだけ出す。外部の OCR サービス・CDN は使わない。
- **日本語の文字認識が使える iOS の版: わかりません。** iOS 16 の `VNRecognizeTextRequestRevision3` で日本語が加わったと記憶しているが、Apple の一次情報をこの環境で開いて確かめていない。プラグインの `supportedLanguages()` で実機の答えを確かめる（下の手順）。

### Mac / iPhone での確かめ手順（この環境ではできない＝**未確認**）
1. Mac で `cd ios-app && npm run setup`（`gohancho-flyer-text` が入り、「チラシの写真プラグイン（FlyerText）が入りました」と出る）。
2. Xcode でビルドして iPhone（実機）で開く。Safari の Web インスペクタでアプリのページを開き、コンソールで
   `await Capacitor.Plugins.FlyerText.supportedLanguages()` → `languages` に `ja-JP` があるか、`revision` を記録する（iOS の版も）。
3. 今日の献立 → 下の「よく行くスーパーの特売」→「チラシを撮る」で、紙のチラシ（新聞の折りこみ）を3枚以上撮る。候補の品名・値段が合っているか、取りちがえ（例: 値段の取りちがえ、品名の読みちがい）を数えて記録する。
4. 機内モードでも同じように読めること（通信しないこと）を確かめる。撮った写真が「写真」アプリ・アプリのデータに残らないことを確かめる。
5. 許可の文（カメラ・写真）が「チラシ」を含んでいるか（setup-ios.sh で更新済み）を確かめる。
