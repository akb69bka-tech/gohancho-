# わが家のご飯帖 App Store の出し方手順書（オーナー用）

作成日: 2026年11月7日　対象: はじめて App Store にアプリを出す、エンジニアではない方
この手順書は、リポジトリ（akb69bka-tech/gohancho-）の既存の資料を読んで、順番に並べ直したものです。**資料に書いていないこと・確かめられないことは、推測で書かず「わかりません」「最新は Apple の公式ページで確認」と書いてあります。**

## この手順書の読み方

- 💴 **お金が発生します（オーナーが判断）** の印がある手順は、お金がかかる、または今後お金の動きが始まる手順です。自動では進めません。あなたが決めてから進めてください。
- 「統括」は、開発チームのまとめ役（桐生 昇）です。「Claude」に頼める作業は、そう書いてあります。
- 画面の名前や料金は Apple が変えることがあります。この手順書の画面名は、リポジトリの資料（2026年10月時点）のものです。**見つからないときは、近い名前の項目を探すか、その画面の写真を Claude に送ってください。**
- 各章の □ は、終わったらチェックを入れる欄です。

### 最初に知っておく言葉（一言で）

| 言葉 | 意味 |
| --- | --- |
| App Store | iPhone のアプリを配るお店 |

## 1. オーナーだけができる準備

名前・住所・カード・銀行口座・本人確認が必要なので、ここは **あなた本人**しかできません。Claude や統括は代わりにできません。

### 1-1. Apple ID の 2ファクタ認証（無料）

2ファクタ認証は「パスワードのほかに、iPhone に届く番号でも確かめる」仕組みです。Apple Developer Program の登録に使います。

- □ 使う Apple ID を決める（iPhone で使っているもので可）。無ければ https://appleid.apple.com/ で作る
- □ その Apple ID の2ファクタ認証をオンにする
- □ 本人確認書類（運転免許証など）を手元に用意する（Apple が求めることがあります）

### 1-2. Apple Developer Program に登録する　💴お金が発生します（オーナーが判断）

アプリを App Store に出すための有料の会員登録です。

- **金額: 最新は Apple の公式ページで確認してください**（https://developer.apple.com/jp/programs/）。リポジトリの資料には「年 99 米ドル（日本では 12,800円と表示）」とありますが、**この手順書の作成時に Apple の公式ページで確かめたものではありません。出典は資料の記述のみで、現在の金額は不明**です。
- 手順（資料 `申請の完全ガイド.md` の「1」より）:
  1. https://developer.apple.com/jp/programs/enroll/ を開き、「登録を開始」→ Apple ID でサインイン
  2. 「個人 / 個人事業主」を選ぶ（法人は D-U-N-S 番号が必要で日数がかかる）
  3. 氏名・住所をローマ字で入力（**App Store の「販売元」に、この名前が表示されます**）
  4. 本人確認（画面の指示どおり）
  5. 年会費を支払う
  6. 「ようこそ」のメールが届いたら完了（承認まで通常 1〜3日）
- □ 登録した
- □ 「ようこそ」のメールを確認した

> 個人か屋号か（運営者名）は、プライバシーポリシーと著作権欄にも使います。docs/escalations.md の A-2 で「運営者名・連絡先・公開日」はオーナーの決定待ちの項目です。

### 1-3. App Store Connect の契約・税・銀行口座

登録の承認後、https://appstoreconnect.apple.com/ に入ります。

- □ 左メニュー「ビジネス」（または「契約/税金/口座情報」）→ **有料 App の契約**をリクエストし、規約に同意
- □ **銀行口座**を登録（売上の受け取り先）
- □ **税務情報**を入力（日本在住の場合、資料では米国の税務フォーム W-8BEN を求められるのが一般的としています。ただし資料自身が **要確認** としているので、画面の案内に従ってください。税のことは **わかりません**。税理士などの専門家に確認を）
- □ 連絡先（法務・財務・マーケティング）を入力（全部あなたでよい）
- □ （公開後でよい）**Small Business Program** に申し込む。手数料の割合が下がる仕組みです。条件と割合は **最新は Apple の公式ページ（https://developer.apple.com/jp/app-store/small-business-program/）で確認**

> 💴 **お金が発生します（オーナーが判断）**: 課金（有料のサブスクリプション）を売るには、この契約・口座・税の登録が必須です（資料の記述）。無料で出すだけの場合に必要かどうかは **わかりません**。統括に確認してください。

### 1-4. Mac と Xcode は必要か

資料の説明が二通りあります。

| 方法 | Mac と Xcode | 資料 |
| --- | --- | --- |
| A. Mac で組み立てる | 必要（Mac と Xcode、Node.js 22 以上） | `申請の完全ガイド.md` の「3」「7-1」 |
| B. GitHub Actions で組み立てる | **不要**（GitHub の上の Mac が組み立てる） | `申請の完全ガイド.md` の付録D、`.github/workflows/ios-release.yml` |

- 資料 `docs/release-management.md` には「初回のみ Mac が必要」と書かれています。一方、付録D は Mac なしでできるとしています。**どちらが正しいかは、まだ実際に動かしていないので わかりません**（`アップデートの手順.md` に「ワークフローはこの環境では実際に動かしていない」とあります）。
- **iPhone は必須**です（TestFlight での実機確認、テスト購入のため）。
- 初回の自動組み立てが失敗したら、そのページの URL を Claude に貼ってください。直します。
- □ 組み立ての方法を A か B に決めた（おすすめは B。Mac が近くになくてもできるため。ただし初回だけ Mac が使える人が近くにいると安心です）

### 2-1. 公開用の本流（main）に、開発の成果を取り込む（PR #3 を Merge する）

**今の状況（2026年11月7日に GitHub で確認）**: PR #3「不具合の総点検と主婦が喜ぶ機能の追加…」（`claude/avoid-swap` → `main`）は **下書き（Draft）の状態**で、まだ Merge されていません。変更は 5,828 ファイル・838 コミットと大きいものです。main は 2026年10月24日から止まっています（資料 `docs/release-management.md`）。

**役割分担**: 統括が「QA（自動テスト）が緑（成功）」であることを確認します。**Merge のボタンを押すのはオーナーです。**

手順:
1. 統括から「QA が緑です。Merge してよいです」と連絡をもらう（**緑でないうちは押さない**）
2. https://github.com/akb69bka-tech/gohancho-/pull/3 を開く
3. 画面の下のほうの **「Checks」に「QA」があり、緑のチェックになっている**ことを自分の目でも確かめる
4. 下書きのままなら **「Ready for review」** を押して下書きを解除する
5. **「Merge pull request」** → **「Confirm merge」** を押す
6. Merge のあと、https://github.com/akb69bka-tech/gohancho-/actions で「Pages」が緑になるのを待つ（2〜3分）

- □ 統括から緑の連絡があった
- □ PR #3 で QA の緑を目で確認した
- □ Merge した

> 注意: Merge は取り消しにくい操作です。迷ったら押さずに統括か Claude に質問してください。実機でしか出ない不具合はありえます（`release-management.md`、**わかりません**）。

### 2-3. Secrets（秘密の値）を6つ登録する

登録場所: https://github.com/akb69bka-tech/gohancho-/settings/secrets/actions → **New repository secret**。名前は `.github/workflows/ios-release.yml` に書かれたものと **1文字も違わず**入力します。値は GitHub の中だけに保存され、Claude からも見えません。**値そのものはチャットや資料に書かないでください。**

| # | 名前（正確に） | 何の値 | どこで取る |
| --- | --- | --- | --- |
| 1 | `APPLE_TEAM_ID` | Apple Developer の Team ID（10桁） | https://developer.apple.com/account →「メンバーシップの詳細」 |
| 2 | `ASC_KEY_ID` | App Store Connect API キーの Key ID | App Store Connect →「ユーザとアクセス」→「統合」→「App Store Connect API」→ チームキー ＋ で作る（名前 `github-actions`、アクセス **App Manager**） |
| 3 | `ASC_ISSUER_ID` | 同じ画面の Issuer ID | 同上（キー一覧の上に表示） |
| 4 | `ASC_API_KEY_P8` | ダウンロードした .p8 ファイルの中身。`-----BEGIN PRIVATE KEY-----` から最後まで全部 | 同上。**.p8 は作成時に1回しかダウンロードできません**（なくしたら作り直し） |
| 5 | `REVENUECAT_API_KEY` | RevenueCat の「Apple 用の公開 API キー」（`appl_` で始まる） | 4章の RevenueCat の設定のあと、「API keys」の「Public app-specific API key」 |
| 6 | `SUPPORT_EMAIL` | 「ご意見・不具合を送る」の宛先メールアドレス | あなたが決める（2-2 の連絡先と同じでよい） |

補足（`ios-release.yml` と `アップデートの手順.md` より）:
- 1〜4 が無いと、組み立てが止まります。5 と 6 が無いと、**審査に出せないビルド**になるため、同じく止まります。
- **TestFlight で試すだけなら**、Actions の「Run workflow」で `allow_free_build` に印を付けると、5 と 6 が無くても組み立てます（課金なし。**そのビルドは審査に出さない**）。
- 署名のエラーが出たときだけ、`IOS_DIST_P12_BASE64` と `IOS_DIST_P12_PASSWORD`（任意の追加2つ）が必要になることがあります。その場合は Claude に相談（Mac が必要になることがあります）。
- API キーの画面の項目名（「クラウド管理による配布証明書へのアクセス」など）は、資料自身が **要確認**（Apple の画面で変わる）としています。
- 5 は RevenueCat の準備が終わってから登録するので、**この時点で4つ（1〜4）と6を先に登録し、5 は4章のあと**に登録してかまいません。

- □ `APPLE_TEAM_ID`　□ `ASC_KEY_ID`　□ `ASC_ISSUER_ID`　□ `ASC_API_KEY_P8`　□ `REVENUECAT_API_KEY`　□ `SUPPORT_EMAIL`

## 4. 課金（定期購入：300円/月・3,000円/年・最初の1か月無料）

資料の決定（オーナー決定 2026-10-31）: 月額 300円、年額 3,000円（月額の12か月分3,600円より600円お得）、どちらも最初の1か月無料。製品の設定値は `ios-app/appstore/kit/03_共通/03_サブスクリプション（製品の設定値）.txt` にあります。

### 4-0. 最初に決めること　💴お金が発生します（オーナーが判断）

アプリの設定（`gohancho/index.html` の `PLAN`）は、今 `billingMode: 'off'`（全員無料）です。課金を有効にする条件は、コードで次の通りです。

- `billingMode` が `'native'` であること（iPhone アプリ版だけで有効。Web 版は無料のまま）
- RevenueCat のキー（Secret `REVENUECAT_API_KEY`）が入っていること

つまり **Secret を登録しただけでは課金は始まらず、`'off'` を `'native'` に変えるコードの変更（Claude に頼めば PR になる）が必要**です。切り替える時期は **オーナー判断**です（`gohancho/index.html` のコメントと `docs/escalations.md`:「課金を始めるか・価格・始める時期」はオーナーの判断）。

| 選択肢 | 内容 | 注意 |
| --- | --- | --- |
| A. 最初は無料で出し、あとで課金を始める | `'off'` のまま審査に出す | 購入画面・「購入を復元」は表示されない（コードで確認）。審査メモと「Appのプライバシー」を無料版の実態に合わせて直す必要があるかは **わかりません**。統括に確認。後から `'native'` にした版を出し直す |
| B. 最初から課金ありで出す | `'native'` に変える PR を Merge してから申請 | 4-1〜4-4 をすべて済ませ、Sandbox で購入と復元を確認してから申請。サブスクをバージョンと一緒に審査に出す |

資料 `docs/escalations.md` には「課金の開始は App Store 公開時」とあり、`申請の完全ガイド.md` は B に近い流れです。**どちらにするかをあなたが決め、統括に伝えてください。**

### 4-2. RevenueCat 側の設定（購入を確かめてくれる外部サービス）

（`申請の完全ガイド.md` の 5-1 より）

1. https://app.revenuecat.com/ でアカウントを作り、プロジェクト `Gohancho` を作る。

- 却下されたら、App Store Connect の「App Review」の本文を **そのまま Claude に貼る**（「/support ＋本文」）。Apple 窓口チーム（`review-responder`）が条項を読み解き、返信文（英語）を作ります（`ios-app/サポート体制.md`）。
- 重大な不具合の修正版は、App Store Connect の「お問い合わせ」から Expedited Review（優先審査）を申請できます。通るまでの時間は資料でも **出典不明**です。
- □ 6-2 の表を読んだ

## 7. 公開後

### 7-1. アップデートの出し方（Claude に頼むだけ）

流れ（`アップデートの手順.md`、`docs/release-management.md`）:

1. 声（App Store のレビュー・メール・Issue）を集める
2. Claude に貼る（または Issue に書く）→ 原因を調べて直し、PR を作る
3. PR の「QA」が緑なら、**オーナーが Merge**
4. Claude に「バージョン 1.1.1 で申請して」と頼む → 「iOS release」が組み立てて App Store Connect へ送る（15〜25分の目安）
5. **オーナーが** App Store Connect で新しいビルドを選び、「審査へ提出」
6. 審査 → 公開

- 2回目からは Mac も Xcode も不要と資料にあります。
- バージョン番号: 直しだけ 1.1.0 → 1.1.1、新機能 1.2.0、大きな作り直し 2.0.0。タグ名は `gohancho-v<版>`（タグでも「iOS release」が動く）。
- 審査なしで変えられるもの: 価格、無料期間、配信国、説明文、スクリーンショット（App Store Connect で変更）、アプリ内のお知らせ（`gohancho/remote.json` の `notice` と `minVersion` を main で直す）。レシピ・翻訳・画面・不具合の直しは審査が必要です。
- 急ぎのとき: まず `remote.json` の `notice` でお知らせ → 修正版を優先審査で出す。
