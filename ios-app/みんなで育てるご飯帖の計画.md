# みんなで育てるご飯帖の計画

作成日: 2026年10月24日。運営者の考え「公開したあと、料理にいいねをつけてもらい、月間の料理自慢を表彰する。世界中のユーザーとアプリを育て、世の中の食卓を豊かにする手伝いをする」を、実際に作れる形にした計画です。

---

## 1. 目指す姿

- 毎日の献立を決める手間を減らす（今のご飯帖の役目）。
- 作った料理を、家族と世界の人にほめてもらえる（新しく足す役目）。
- 使う人の声と料理で、レシピと翻訳がよくなっていく（育てる役目）。

## 2. 3つの段階で進める

いきなり「みんなの投稿」を作ると、サーバー・審査・見守りの準備が一度に必要になります。先に、サーバーなしでできる「わが家の料理自慢」で、ほめられるうれしさを作ります。

| 段階 | 中身 | サーバー | Apple の審査で増える条件 |
| --- | --- | --- | --- |
| 0（すぐ作れる） | 作った料理に家族の反応（おいしかった！など）を付ける。月のおわりに「今月のわが家の料理自慢」を記録タブで表彰する。反応が多い料理は献立に出やすくする | いらない | なし |
| 1 | 作った料理の写真を投稿し、世界の人がいいねを付ける。国ごとと世界で「今月の料理自慢」を表彰する | いる | 投稿の見守り・通報・ブロック、アカウント削除、プライバシーの書き直し |
| 2 | 使う人が「うちの国ではこう作る」「この訳は変」を送れる。運営が確かめて次の版に入れ、採用した人の名前（ニックネーム）をレシピに載せる。「今月の採用レシピ」も表彰する | いる（段階1と同じ） | 段階1と同じ |

## 3. 段階1で守ること（審査と安心のため）

| 決まり | 中身 | 根拠 |
| --- | --- | --- |
| 投稿の見守り | 不適切な写真・文を自動で弾く。通報ボタンを付ける。迷惑な人をブロックできる。運営の連絡先を載せる | App Store Review Guidelines 1.2 User-Generated Content |
| アカウント削除 | アプリの中から、アカウントと投稿を消せるようにする | 同 5.1.1(v) |
| ログイン | Google などのログインを使うなら、Sign in with Apple も用意する | 同 4.8 |
| 表彰と賞品 | 賞品やお金を出さず、称号とバッジだけにする。賞品を出すなら、運営が主催し、公式のルールを載せ、Apple は関係ないと書く | 同 5.3 |
| 写真の位置情報 | 投稿する前に、写真に入っている撮影場所の情報を消す | 家の場所が知られないため（運営の判断） |
| 名前 | 本名ではなくニックネームを使う。子どもの顔などは投稿しないよう案内する | 同上 |
| いいねの公平さ | 1人1回、自分の投稿には付けられない。短い時間に大量のいいねは数えない | 表彰の信頼のため |
| プライバシー | 「データは端末の中だけ」の説明を、投稿する人だけ例外として書き直す。App Store のプライバシーの表示も変える | 同 5.1 |

参照: https://developer.apple.com/app-store/review/guidelines/

## 4. 段階1の作り方の案

| 部品 | 案 | 費用の目安 |
| --- | --- | --- |
| ログイン・データ・写真 | Firebase（Authentication・Firestore・Storage）または Supabase | 少ない人数のうちは無料の範囲で始められる。人数が増えると使った分の支払い（金額は利用者数しだいで、**わかりません**） |
| 写真の見守り | 投稿時に自動判定（例: Google Cloud Vision の SafeSearch）＋通報されたものを運営が確認 | 1枚ごとに少額（**わかりません**。公式の料金表で確認） |
| 月間の表彰 | 月末に自動で集計し、国ごと・世界の上位を決める（運営が最後に確認） | 上と同じ範囲 |

段階1を始める前に、運営者が決めることです。

1. やるかどうか、いつから始めるか。
2. 運営者名・連絡先（今もプライバシーポリシーとサポートページが下書きのままです）。
3. 月の予算の上限。
4. 表彰を称号だけにするか、賞品を出すか（おすすめは称号だけ）。

## 5. 段階0の内容（次に作る）

- 料理の詳しい画面と作り方タブの「作った」のあとに、家族の反応を1タップで付ける（例: 「また作って！」「おいしかった」「ふつう」）。
- 記録タブに「今月のわが家の料理自慢」を出す。反応がいちばん多かった料理を表彰し、月ごとに残す。
- 反応の多い料理は献立に少し出やすく、「ふつう」が続く料理は少し出にくくする。
- 家族に送る文に「今月の料理自慢」を入れられるようにする。

## 6. 今回のテストで見つかった不具合と、使いやすくする案

4人の担当がアプリ全体を試し、高い重要度が約12件、中が約25件、低が約30件見つかりました。5人の担当で直しています。主なものは次のとおりです。

| 重要度 | 内容 |
| --- | --- |
| 高 | 苦手な食材の入力で、別の食材として登録される（eggplant が卵、peanuts がくるみ） |
| 高 | 苦手を「豚肉」にしても、ひき肉・ハム・ベーコンの料理が出る |
| 高 | 献立を2回決めると、作っていない料理まで「作った」と記録される |
| 高 | おまかせ品数だと、決めた献立が開き直すと消える |
| 高 | 日本語以外で日本の料理を使うと、日本語の「ひとひねり」カードが混ざる |
| 高 | プライバシーポリシーとサポートページが下書きのまま（運営者の情報が必要） |
| 中 | 買い物メモで、別の食材が1行にまとまり量が間違う |
| 中 | 検索で、ひらがな（みそ汁・ぎょうざ）や英語名（pad thai）で見つからない |
| 中 | 電波がないときに開くと、アプリではなくプライバシーポリシーが出ることがある |
| 中 | ほかの国の料理をお気に入り・記録にすると、開き直したあとに開けない |

使いやすくする案（採用して作るもの）:

1. 手順の「8分」を押すとタイマーが始まる。
2. 苦手な食材を「豚肉（ひき肉・ハム・ベーコンも）」のような大きな分類で選べる。
3. 買い物メモを売り場ごと（野菜・肉と魚・乳製品と卵・その他）に分け、チェックしたものは下へ。
4. 決める前の献立も、その日のうちは同じものを出す。
5. 料理をひらがな・英語名・現地の名前でも探せる。
6. 献立を決めた直後に「取り消す」。
